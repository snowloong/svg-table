# SVG 表格设计

本项目旨在探索如何利用 SVG、WebComponent 以及 Web Worker 技术，打造高性能、可扩展的虚拟滚动表格组件。通过自研虚拟滚动、节点池复用、分层渲染等机制，解决大数据量下表格渲染与交互的性能瓶颈，适用于对性能和可视化有较高要求的业务场景。

## 技术选型

| 层级/功能         | 技术选型                | 说明/理由                                 |
|------------------|------------------------|------------------------------------------|
| 组件封装         | Omi                    | 轻量、React 风格、原生支持 WebComponent  |
| 渲染层           | 原生 SVG API           | 灵活、性能好，适合可视化和动画            |
| 虚拟滚动         | 自研                   | 行列双虚拟化，适配 SVG，灵活性高          |
| 数据处理         | Web Worker（+ comlink）| 主线程不卡顿，comlink 简化通信（可选）    |
| 编辑控件         | 原生 DOM + 绝对定位    | 兼容性好，体验佳，易于实现复杂交互        |
| 动画             | 手动实现 FLIP 动画     | 细粒度控制，完全自定义，适配 SVG 场景     |
| 状态管理         | Omi 内置 reactive-signal| 简单高效，适合中小型项目                  |
| 生态/集成        | 原生/自研              | 组件可独立使用，也可集成到主流框架         |

## 主要功能与实现思路

### 1. 大数据支持
- 支持万级甚至更大数据量，主线程只渲染可见区域，不卡顿。
- 数据的排序、过滤、分组等重计算任务交由 Web Worker 处理，主线程专注渲染和交互。

### 2. 虚拟滚动/虚拟列
- 只渲染当前视口内的行和列（如可见50行×50列），其余数据不渲染，极大减少 SVG 节点数量。
- 滚动或横向滚动时，复用 SVG 节点，动态更新内容和位置。

### 3. 动态列宽与列顺序调整
- 支持用户拖拽调整列宽，所有可见单元格的宽度和位置实时更新。
- 支持拖拽调整列顺序，采用 FLIP 动画原理实现平滑过渡。

### 4. SVG 渲染
- 每个单元格用 SVG 元素（如 `<rect>`、`<text>`）渲染。
- 表头、表体分层渲染，便于固定表头和性能优化。

### 5. 行/单元格编辑能力
- 支持单元格编辑、行编辑。
- 编辑时用 HTML DOM 元素（如 `<input>`、`<select>`、`<textarea>`）绝对定位叠加在 SVG 上方。
- 编辑完成后，将数据同步回表格数据源，并重新渲染 SVG。
- 支持键盘导航（Tab、Enter、Esc）、批量编辑、校验等高级功能。

#### 编辑流程示例
1. 用户点击单元格/行，计算该单元格/行在页面上的绝对位置。
2. 在 SVG 上方插入一个 HTML 编辑控件，并用 CSS 绝对定位到对应位置。
3. 用户编辑完成后，将新值同步到数据源，销毁编辑控件，SVG 重新渲染新内容。

## Web Worker 方案优势

- **开发门槛低**：直接用 JavaScript 编写，无需 WASM 相关知识和工具链。
- **性能足够**：对于万级数据的排序、过滤等，Web Worker 性能已能满足绝大多数业务需求。
- **主线程不卡顿**：数据处理在 Worker 线程中进行，UI 渲染流畅。
- **易于维护和调试**：Worker 代码可直接在浏览器调试，易于排查问题。

## 与现有 Ant Design Table 方案对比

| 维度             | Ant Design Table（现有） | SVG+WebComponent+Web Worker（新方案）   |
|------------------|-------------------------|----------------------------------------|
| 渲染方式         | HTML+CSS                | SVG                                    |
| 组件生态         | 成熟、丰富              | 需自研，生态较少                       |
| 虚拟滚动         | 有现成方案              | 需自研，需处理行列双虚拟化             |
| 列宽拖拽         | 内置/社区方案           | 需自研，SVG属性控制                    |
| 列顺序拖拽       | 插件/自定义             | 需自研，结合FLIP动画                   |
| 性能（万级数据） | 需配合虚拟滚动优化      | 虚拟滚动+Worker，理论上更优            |
| 可视化能力       | 一般                    | 极强（SVG可任意绘制、动画）            |
| 维护成本         | 低                      | 高（需自研、测试、维护）               |
| 兼容性           | 高                      | WebComponent需现代浏览器，SVG兼容好    |

## 可行性结论

- **技术上完全可行**，SVG+虚拟滚动+Web Worker 能实现高性能和高度自定义的表格。
- **开发难度和维护成本高于 Antd Table**，但比 WASM 方案低，适合有自研能力的团队。
- **适合对性能、可视化、交互有较高要求的场景**，如金融、监控、科学计算等。
- **如只是常规业务表格，Antd Table+虚拟滚动+自定义渲染已足够，迁移意义不大。**
