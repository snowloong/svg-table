# 背景

SVG 虚拟滚动表格组件在大数据量场景下，为了保证渲染性能和流畅交互，采用了虚拟滚动和节点池复用机制。该机制的核心是只渲染可见区域的 SVG 节点，并在滚动时复用这些节点，极大减少 DOM 操作和内存消耗，是高性能表格的基础。

---

## 实现细节
- 通过计算当前滚动位置、视口尺寸、单元格尺寸，确定可见的行列范围。
- 维护一组固定数量的 SVG 节点池，节点数量等于最大可见单元格数。
- 滚动时，仅更新节点池内 SVG 元素的内容和 transform 属性，不频繁创建/销毁节点。
- 节点池的增删仅在表格尺寸或可见区域变化时发生，绝大多数滚动场景只做属性变更。
- 支持行/列的动态增删，节点池可自适应扩容或缩减。

---

## 待解决问题
- 大数据量下 SVG 节点数量与性能瓶颈的边界：如何确定节点池的最优规模？
- 节点池复用时的极端滚动、快速跳转等异常处理：如何保证内容和位置的同步？
- 节点池与分层渲染（如表头、表体、选中等）的协同机制。
- 节点池内节点的唯一标识与数据绑定策略，避免渲染错位。
